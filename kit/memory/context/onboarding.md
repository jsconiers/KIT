# Onboarding setup

What the onboarding guide uses. It reads this before every job, so keep it current.

- **Core reading, architects:** not set. The templates, standards, and example documents a new
  architect should read first, in order.
- **Core reading, project managers:** not set. The life cycle, intake, status, and governance
  documents a new project manager should read first, in order.
- **Kit training path:** `ONBOARDING.md` (in `.install/`): install, first day, daily rhythm,
  approvals, what Kit never does, setup files, and the first-week checklist, in that order. Add
  team-specific steps here.
- **Team conventions:** not set. Where the team's templates, standards, and ways of working are
  written down. The guide also uses the library, the knowledge base, and Kit's setup files.
- **Off limits:** Kit's queue, briefs, lessons, preferences, and personal notes, always. Add any
  folders or documents the guide must never read or quote.
- **Sharing:** follow `knowledge.md`. Say here if onboarding answers may be shared more widely or
  less widely than that.
